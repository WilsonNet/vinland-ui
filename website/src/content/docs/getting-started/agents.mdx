Drive a running app from the terminal: navigate, click, type, and take screenshots. Built for AI agents and tests.

Every vinland-ui app can expose a local control port. `vui-ctl` speaks to it, which gives agents and tests the same feedback loop a person gets from looking at the screen.

## Run an app headless

```sh
# render offscreen at a fixed scale; nothing appears on your desktop
VUI_HIDDEN=1 VUI_SCALE=2 VUI_SIZE=1440x900 ./build/showroom &

./build/vui-ctl info
./build/vui-ctl nav page=box-shadow
./build/vui-ctl dark on
./build/vui-ctl screenshot shadow-dark.png
./build/vui-ctl click-text "Show all"
./build/vui-ctl scroll 600
./build/vui-ctl tree 6 | jq '.nodes[] | select(.t)'
```

## Drive a visible app without stealing input

Pointer and key commands are injected inside the app: they never warp or click the real OS pointer, raise the window or request focus. When the window should stay visible while someone else uses the machine, start it with `VUI_BACKGROUND=1`. It is mapped without activation and with the non-focusable hint (plus `SDL_MAC_BACKGROUND_APP=1` on macOS so no Dock icon or focus steal occurs), so a game or editor normally keeps keyboard and pointer focus. X11 window managers and macOS honor the hints; Wayland leaves focus policy to the compositor, where a no-focus rule is the reliable option.

```sh
VUI_BACKGROUND=1 VUI_PORT=7420 ./build/my_app &
./build/vui-ctl info          # background:true, focusable:false, keyboard_focus:false
./build/vui-ctl click-text "Save"
./build/vui-ctl foreground    # escape hatch: native dialog, IME, human takeover
./build/vui-ctl background    # back to non-focusable driving
```

A compositor may refuse to make an existing Wayland surface focusable; the foreground response reports that, and restarting without `VUI_BACKGROUND=1` is the fallback for flows that need native focus.

## Commands

| Class | Effect |
| --- | --- |
| `info` | `viewport, scale, frame time, backend/driver, focus state, node count, unknown classes, hot reload status (hot)` |
| `screenshot <png> [x y w h]` | `writes the last frame (optionally cropped)` |
| `click <x> <y> [right\|double\|triple]` | `synthetic click in logical px` |
| `click-text <text> [nth]` | `clicks the element whose text matches` |
| `move / scroll / type / key` | `pointer, wheel and keyboard input` |
| `foreground / background` | `opt into OS focus / return to non-focusable driving` |
| `release` | `drop a stuck synthetic button or drag` |
| `resize <w> <h> / dark [on\|off]` | `window size and color scheme` |
| `tree [depth]` | `element tree with rects, classes and text as JSON` |
| `settle / wait [frames]` | `block until animations finish` |
| `<app command> key=value` | `forwarded to App.on_command (nav, pages, search...)` |

## Agent skill

The repository ships `skills/vinland-ui/SKILL.md` (symlinked at `.agents/skills/vinland-ui` for automatic agent discovery). It teaches the element API, the utility vocabulary, the token system and this CLI loop, so an agent can build a screen, screenshot it and iterate without a human in the loop.
